# engineering-dialectic

Заготовка read-only оркестратора для инженерных решений. Метод и примеры находятся
в [skill](../../skills/engineering-dialectic/SKILL.md). Адаптер первой версии
предназначен для OpenCode V2; профили Claude Code/Codex пока не зарегистрированы.
Канонический файл агента не следует устанавливать старым универсальным
`install-opencode-agent.sh`: тот не переносит ограничения этой группы профилей.

## Состав

- `engineering-dialectic.md` — источник инструкций ведущего.
- `../../skills/engineering-dialectic/references/role-prompts.md` — источник ролей.
- `build_opencode.py` — собирает пять самодостаточных профилей из источников.
- `adapters/opencode/` — сгенерированные профили V2; не редактируются вручную.
- `verification.md` — сценарии и фактическая проверка заготовки.

Защита варианта добавлена отдельным пятым профилем, чтобы поддержать positions
без превращения слепого решателя в другую роль. Подробности метода остаются
в skill; промпты ролей встраиваются при сборке, чтобы исполнители не читали
общий журнал или все примеры перед независимым решением.

## Сборка и установка в проект

Нужны Python 3, PyYAML и OpenCode V2. Из корня checkout:

```bash
python3 agents/engineering-dialectic/build_opencode.py
python3 agents/engineering-dialectic/build_opencode.py --check
bash scripts/package-skill.sh engineering-dialectic
```

Установка выполняется отдельно в выбранный проект. Сначала проверь существующие
файлы: сборщик отказывается заменять чужие профили, но может обновлять собственные
сгенерированные. `install-local.sh` заменяет одноимённую папку skill.

```bash
PROJECT=/absolute/path/to/project
python3 agents/engineering-dialectic/build_opencode.py \
  --output "$PROJECT/.opencode/agents"
INSTALL_DIR="$PROJECT/.opencode/skills" \
  bash scripts/install-local.sh engineering-dialectic --target opencode
```

По умолчанию модель не зашита: субагенты наследуют выбранную модель. Модель
выбирает пользователь; при необходимости пересобери устанавливаемые профили
с `--model`, передав реальный идентификатор `provider/model` с вариантом.
Ведущий не перебирает каталог моделей и только фиксирует фактическую. Выбор
primary-профиля сам по себе может не менять модель уже открытой сессии —
проверь её в интерфейсе.

В новом сеансе выбери primary-агента `engineering-dialectic`. Вместо ручного
выбора можно поставить необязательную команду `/dialectic` из skill
(`scripts/install_commands.py --host opencode --dest <project>`). Пример:

> Спроектируй обработку повторной доставки заказа с engineering-dialectic,
> independent. Вот требования, код обработчика и контракт брокера. Нужен
> план, а не изменение кода.

## Что ограничено технически

Профиль ведущего запрещает всё, кроме локального чтения/поиска, загрузки этого
skill и вызова четырёх перечисленных профилей. Он не пишет даже decision.md:
возвращает текст пользователю или родительскому агенту для сохранения.

У всех исполнителей `permissions: deny *`. Они получают материалы сообщениями
и не могут читать скрытый журнал, запускать shell, сборки, SQL, web или MCP.
Это консервативная начальная конфигурация. Если материалов мало, исполнитель
запрашивает дополнительные первичные выдержки у ведущего. Отбор ведущим остаётся
ограничением полноты и должен быть указан в отчёте.

Права инструментов не блокируют автоматически добавление проектных инструкций
в системный контекст. Перед запуском нужно проверить отсутствие исходного
вывода в этих инструкциях и памяти; при загрязнении заявлять частичную слепоту
(поле `blindness`: `full` / `partial` / `compromised`).
Настройку непосредственного read-only доступа исполнителей к чистому снимку
или проверенному SQL-инструменту эта заготовка не автоматизирует.

## Совместимость

OpenCode V2 использует `permissions`, `shell`, `subagent`; V1 имеет другой формат.
Не устанавливай эти профили в V1 с надеждой, что ограничения будут распознаны.
См. [Agents](https://opencode.ai/docs/agents/),
[Permissions](https://opencode.ai/docs/permissions/) и
[Skills](https://opencode.ai/docs/skills/). Проверка структуры конфигурации не
равна доказательству фактической изоляции всех версий среды.
