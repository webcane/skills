# cane-learning

Агент готовит технические учебные статьи с несколькими примерами применения
и заданиями по методологии **Master Prompt v2.0 — Concept Learning Article
Writer**. Один агент последовательно выполняет четыре роли и сохраняет промежуточные результаты.

## Подключение к проекту

Выполни нужную команду из корня этого репозитория.

Для Claude Code:

```bash
INSTALL_DIR="$PWD/.claude/agents" bash scripts/install-agent-local.sh cane-learning
```

Для Codex:

```bash
mkdir -p .codex/agents
cp agents/cane-learning/cane-learning.codex.toml .codex/agents/cane-learning.toml
```

Открой новую сессию в проекте. В Claude Code проверь список через `/agents`.
В Codex явно попроси делегировать подготовку статьи агенту `cane-learning`.

Без `INSTALL_DIR` скрипт устанавливает агент в пользовательский каталог
Claude Code `~/.claude/agents/`. Для пользовательской установки в Codex
помести TOML в `~/.codex/agents/cane-learning.toml`. При запуске из другого
репозитория агент найдёт оркестратор по ссылке `~/.local/share/cane-learning`
или по абсолютному пути в переменной `CANE_LEARNING_HOME`.

## Проверка артефактов

Агент выполняет стадии в своей сессии, сохраняя JSON в рабочем каталоге.
Python 3.11+ нужен для проверки контрактов и сборки статьи. После каждой стадии
агент запускает `python3 validate_run.py <каталог-раунда> --through <роль>`.
После успешной проверки рецензента команда с `--publish` создаёт `article.md`.

`pipeline.toml` задаёт метаданные, глубину и число доработок. Исходный
`cane_learning.py` остаётся доступным как отдельный CLI-конвейер для
воспроизводимого теста и самостоятельных экспериментов.

## Выбор настроек

Вызови агента без темы или попроси «покажи настройки» — он перечислит форматы,
глубину, аудиторию, цель и другие параметры. Можно указать их свободным текстом,
например: «Краткий конспект Java 21 HashMap для повторения, глубина standard».

Если тема уже задана, агент кратко покажет выбранные формат и глубину и начнёт
работу. По умолчанию используются учебная статья, глубина standard, опытный
разработчик, практическая цель и язык запроса. Необходимые отсутствующие
параметры и неоднозначный формат агент уточняет.

## Проекции

Параметр `projection` выбирает формат результата. По умолчанию — `article`.

| Значение | Результат |
| --- | --- |
| `article` | Учебная статья с несколькими применениями и заданиями |
| `summary` | Краткий конспект для повторения |
| `concept` | Смысловая модель концепции |
| `internals` | Внутреннее устройство конкретной реализации |

Агент определяет проекцию по запросу и уточняет выбор, если формулировка
допускает несколько вариантов. Во всех проекциях сохраняется внутренний банк
проверок. За пределами `article` упражнения публикуются по запросу.

## Контракты и возврат на доработку

| Стадия | Вход | Выход |
| --- | --- | --- |
| Knowledge Analyst | Учебный запрос | `ConceptModel` с P0/P1/P2, источниками, условиями, механизмами и контрольными случаями |
| Learning Designer | Запрос и `ConceptModel` | `LearningSpec` с разреженной матрицей, банком заданий, критериями и выборкой для статьи |
| Technical Writer | Запрос, `ConceptModel` и `LearningSpec` | `ArticleDraft` с Markdown-разделами и связями с моделью и компетенциями |
| Quality Reviewer | Запрос и все три артефакта | `QualityReport` с вердиктом, цитатами для обязательных клеток и адресными замечаниями |

Инструкции находятся в `methodology.md` и `stages/`. Схемы обмена в `schemas/` описывают JSON. Проверка контрактов контролирует форму, уникальность ID, связи, обязательные клетки, привязку задач к критериям и наличие дословной цитаты. Рецензент оценивает фактическую корректность, пригодность цитаты как доказательства и педагогическое качество.

При блокирующем замечании агент возвращается к самой ранней из затронутых ролей и повторяет все последующие стадии. Уже принятые артефакты копируются в новый раунд. Роль получает свой предыдущий результат и отчёт рецензента. Каждая доработка заканчивается новой проверкой всего комплекта. По умолчанию доступны две доработки. Публикация возможна после `pass` и машинных проверок.

В каталоге запуска сохраняются запрос и отдельная папка для каждого раунда. Для прогона через CLI там также остаются журналы и исходные ответы исполнителя. При успехе `result.json` указывает раунд публикации, а `article.md` содержит статью и выбранные упражнения. При исчерпании доработок остаётся отчёт с последними замечаниями. Коды выхода — `0` при публикации, `1` при исчерпании доработок, `2` при ошибке входа, исполнителя или контракта.

## Воспроизводимый пример

```bash
python3 cane_learning.py examples/hashmap/request.toml \
  --replay examples/hashmap/replay --out runs/hashmap-replay
```

Воспроизведение работает без Codex и использует подготовленные JSON-ответы. В первом черновике намеренно внесена ошибка о гарантированном `null` после изменения ключа. Reviewer возвращает её Writer, затем подтверждает покрытие трёх обязательных клеток. Три задачи опубликованы, четвёртая осталась в банке. Сохранённый результат — [статья о HashMap](examples/hashmap/article.md).

Этот прогон проверяет контракты, маршрутизацию, повторную проверку и публикацию. Пробный запуск с моделью в среде сборки остановился при инициализации Codex CLI из-за ограничений доступа. Качество автоматической генерации требует отдельного прогона в настроенной среде.

## Соответствие Master Prompt v2.0

| Исходные разделы | Где выполняются |
| --- | --- |
| 1–2 и 19 · цель и разделение моделей | Учебный запрос, общие правила и оркестратор |
| 3–7 · грани, приоритеты, инварианты, механизмы, примеры, SICP | Knowledge Analyst |
| 8–11 · восемь компетенций, адаптивная матрица, Coding Skills Hierarchy, банк задач | Learning Designer |
| 12–16 · порядок объяснения, достаточность, сквозной пример и закрепление | Technical Writer и сборка статьи |
| 9.5–9.10 и 17 · объяснение, проверка и трассируемость | Quality Reviewer и валидация ссылок |
| 18 · итоговый формат | Markdown-статья отдельно от рабочих JSON |
