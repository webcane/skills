# cane-learning

MVP подготовки технических учебных статей по методологии **Master Prompt v2.0 — Concept Learning Article Writer**. Автор проекта — **Cane**. Один оркестратор последовательно запускает четыре роли. При запуске через Codex CLI каждая роль получает отдельный вызов с нужными входными данными.

## Подключение агента

Агент хранится в `cane-learning.md` для Claude Code и в сгенерированном
`cane-learning.codex.toml` для Codex. Оркестратор и его ресурсы остаются
в этом каталоге репозитория. Для запуска из другого проекта используй
ссылку `~/.local/share/cane-learning` на этот каталог или укажи его абсолютный
путь в переменной `CANE_LEARNING_HOME` перед стартом клиента.

Из корня репозитория для Claude Code:

```bash
bash scripts/install-agent-local.sh cane-learning
```

Для Codex помести `cane-learning.codex.toml` в каталог пользовательских
агентов как `cane-learning.toml`. Затем начни новую сессию и укажи, что
учебный материал должен подготовить агент `cane-learning`.

## Быстрый запуск оркестратора

Нужен Python 3.11 или новее. Для прогона с моделью также нужен настроенный Codex CLI с поддержкой `codex exec --output-schema`. Команды запускаются из каталога проекта. Значение `--out` должно указывать на новый каталог.

```bash
python3 cane_learning.py examples/hashmap/request.toml --out runs/hashmap
```

Для своей темы скопируйте `examples/hashmap/request.toml` и измените тему, технологию и версию. Аудитория, цель, язык текста и глубина имеют значения по умолчанию. В запрос можно добавить ограничения и список известных источников. Режимы `focused`, `standard` и `deep` меняют охват P1/P2, глубину причинного объяснения и число публикуемых задач. P0 входят во все режимы.

`pipeline.toml` задаёт метаданные, команду исполнителя, таймаут и число доработок. Команда исполнителя должна принимать промпт через стандартный ввод и записывать JSON в файл, указанный через `--output-last-message`. При запуске передаётся схема через `--output-schema`. Отдельных зависимостей Python нет.

## Контракты и возврат на доработку

| Стадия | Вход | Выход |
| --- | --- | --- |
| Knowledge Analyst | Учебный запрос | `ConceptModel` с P0/P1/P2, источниками, условиями, механизмами и контрольными случаями |
| Learning Designer | Запрос и `ConceptModel` | `LearningSpec` с разреженной матрицей, банком заданий, критериями и выборкой для статьи |
| Technical Writer | Запрос, `ConceptModel` и `LearningSpec` | `ArticleDraft` с Markdown-разделами и связями с моделью и компетенциями |
| Quality Reviewer | Запрос и все три артефакта | `QualityReport` с вердиктом, цитатами для обязательных клеток и адресными замечаниями |

Инструкции находятся в `methodology.md` и `stages/`. Схемы обмена в `schemas/` описывают JSON. Оркестратор проверяет форму, уникальность ID, связи, обязательные клетки, привязку задач к критериям и наличие дословной цитаты. Рецензент оценивает фактическую корректность, пригодность цитаты как доказательства и педагогическое качество.

При блокирующем замечании оркестратор возвращается к самой ранней из затронутых ролей и повторяет все последующие стадии. Уже принятые артефакты копируются в новый раунд. Роль получает свой предыдущий результат и отчёт рецензента. Каждая доработка заканчивается новой проверкой всего комплекта. По умолчанию доступны две доработки. Публикация возможна после `pass` и машинных проверок.

В каталоге запуска сохраняются запрос и отдельная папка для каждого раунда. Для прогона через CLI там также остаются журналы и исходные ответы исполнителя. При успехе `result.json` указывает раунд публикации, а `article.md` содержит статью, карточку и выбранные упражнения. При исчерпании доработок остаётся отчёт с последними замечаниями. Коды выхода — `0` при публикации, `1` при исчерпании доработок, `2` при ошибке входа, исполнителя или контракта.

## Воспроизводимый пример

```bash
python3 cane_learning.py examples/hashmap/request.toml \
  --replay examples/hashmap/replay --out runs/hashmap-replay
```

Воспроизведение работает без Codex и использует подготовленные JSON-ответы. В первом черновике намеренно внесена ошибка о гарантированном `null` после изменения ключа. Reviewer возвращает её Writer, затем подтверждает покрытие трёх обязательных клеток. Три задачи опубликованы, четвёртая осталась в банке. Сохранённый результат — [статья о HashMap](examples/hashmap/article.md).

Этот прогон проверяет контракты, маршрутизацию, повторную проверку и публикацию. Пробный запуск с моделью в среде сборки остановился при инициализации Codex CLI из-за ограничений доступа. Качество автоматической генерации требует отдельного прогона в настроенной среде.

## Соответствие Master Prompt v2.0

| Исходные разделы | Где выполняются |
| --- | --- |
| 1–2 и 19 · цель и разделение моделей | Учебный запрос, общие правила и оркестратор |
| 3–7 · грани, приоритеты, инварианты, механизмы, примеры, SICP | Knowledge Analyst |
| 8–11 · восемь компетенций, адаптивная матрица, Coding Skills Hierarchy, банк задач | Learning Designer |
| 12–16 · порядок объяснения, достаточность, сквозной пример и закрепление | Technical Writer и сборка статьи |
| 9.5–9.10 и 17 · объяснение, проверка и трассируемость | Quality Reviewer и валидация ссылок |
| 18 · итоговый формат | Markdown-статья отдельно от рабочих JSON |
