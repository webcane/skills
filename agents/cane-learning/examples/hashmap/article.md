# Как Java HashMap находит ключ

## Какому пользователю принадлежат баллы

Сервис начисляет баллы пользователям. Запрос приходит с числовым идентификатором. При каждом запросе можно создать новый объект `UserId` и найти прежнюю запись, если объекты с одним идентификатором равны.

```java
record UserId(long value) {}

var points = new java.util.HashMap<UserId, Integer>();
points.put(new UserId(42), 10);
points.put(new UserId(42), 15);
System.out.println(points.size());              // 1
System.out.println(points.get(new UserId(42))); // 15
```

Повторный put с равным ключом заменяет значение существующей записи. У этих экземпляров record один и тот же компонент, поэтому ключи равны. У равных объектов `hashCode()` должен совпадать. Иначе структура, использующая хеш для поиска, может пропустить равный ключ. [Контракты Map](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Map.html) и [Object](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Object.html).

## Что происходит при коллизии

В OpenJDK 21 `HashMap` вычисляет хеш для ключа и по нему выбирает корзину. Внутри неё реализация ищет подходящую запись, проверяя сохранённый хеш и ключ. Хеш сужает поиск, а равенство ключей определяет совпадение. Строки `Aa` и `BB` имеют одинаковый хеш, но сравнение через `equals` различает их. После двух записей карта хранит оба значения.

Это объяснение устройства OpenJDK 21. Детали выбора корзины зависят от реализации. [Исходный код HashMap](https://github.com/openjdk/jdk/blob/jdk-21%2B35/src/java.base/share/classes/java/util/HashMap.java).

## Почему имя пользователя годится для значения, но рискованно для ключа

Представь, что ключом стал объект пользователя, а `equals` и `hashCode` зависят от его редактируемого имени. Запись была размещена по старому хешу. После переименования поиск может начаться в другой корзине, даже если в `get` передан тот же объект. По контракту `Map` результат такого поиска не определён, если изменение влияет на сравнение ключа через `equals`. [Контракт Map](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Map.html).

Возьми неизменяемый ID, чтобы изменение имени не влияло на равенство ключа. Если ID берётся из исходной записи и остаётся прежним, новое имя не меняет `UserId`. Такую схему можно перенести на заказы или документы с редактируемыми названиями.

## Итоговая карточка

- `put` заменяет значение по равному ключу.
- Коллизия означает совпадение хеша, а ключи могут быть разными.
- Поля, определяющие равенство ключа, должны сохраняться всё время хранения.

### 1. Задание
