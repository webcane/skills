# pes Changelog

## [Unreleased]
- Renamed the `ingest` command/workflow to `capture` (`workflows/ingest.md` → `workflows/capture.md`) throughout SKILL.md, README.md, and the rule files.
- Added `init` workflow: bootstraps the six-list skeleton (+ WIP Limit entry) on first use or on request, idempotent. Pre-flight in `SKILL.md` now checks for the skeleton (not just MCP connectivity) and offers `init` before proceeding against a partial structure — fixes ad-hoc `tasks create` silently writing into a system that was never set up.
- Fixed: Task creation no longer defaults silently to an unlinked reminder. Every Task now gets exactly one classification tag — `plan-<slug>` (pes task) or `adhoc` (ad-hoc task) — resolved deterministically (named Plan → explicit ad-hoc → ask once only if genuinely ambiguous). `lint` now flags Tasks with neither tag (or both) instead of treating unclassified Tasks as unavoidable noise. (Terminology note: "ad-hoc task", not "activity" — `Task = activity` is already how `rules/outcomes.md` distinguishes Task from Outcome/Result, so reusing "activity" here would collide with that meaning.)
- Initial release: PML (Strategic/Tactical/Operational) agent over Apple Reminders + Calendar via `mcp-server-apple-events`, router `SKILL.md` dispatching to twelve workflows (`init`, `capture`, `lint`, `status`, `tasks`, `plans`, `results`, `review`, `retrospective`, `routines`, `plan-week`, `execution`).
- Seven rule files: `architecture`, `invariants` (17 hard rules), `priorities` (Strategic vs Operational vs urgency), `outcomes` (Task/Outcome/Result + activity-over-outcome), `autonomy` (confirmation boundaries + read→propose→diff→confirm→write→verify), `data-model` (Reminders lists/tags/notes conventions), `mcp-tools` (MCP schemas verified against `mcp-server-apple-events` v1.5.0 source, plus documented gaps: no recurring-event write, no `flag` field, no nested lists).
- WIP limit (default 3, configurable via a `Strategic`/`WIP Limit` reminder), Plan-requires-Initiative-and-Expected-Outcome gate, Task decomposition proposal flow, Strategic-Level changes always gated on explicit user confirmation.
