# Workflow: execution

Execution mode ([rules/autonomy.md](../rules/autonomy.md)) — helping the user
work through what's already planned, not planning or re-planning.

## Steps

1. Read current Tasks: due today, overdue, and (if the user names a Plan)
   Tasks tagged to that Plan.
2. Surface priority: sort by Operational Priority then `dueDate`; mention
   Strategic Priority context only if the user asks or if it's directly relevant
   to a choice between two Tasks.
3. Show the next action set — 1–3 Tasks (Rule of 3), not the full backlog, unless
   asked for the full list.
4. Help close Tasks as the user finishes them — hand off to
   [tasks.md](tasks.md)'s `complete` (light-touch, single-Task).
5. Help record Results as they come up — hand off to
   [results.md](results.md) (full write-flow, since recording a Result always
   needs confirmation).

## Hard boundary

**Never, during execution, revisit Strategy or start a new Initiative on your
own.** A new idea that surfaces here — even one that looks directly relevant to
what's being worked on — goes to [capture.md](capture.md), full stop (invariant 7).
If the user explicitly asks to pivot ("actually let's change the Plan"), that's
them switching out of Execution mode into a Plan update — treat it as
[plans.md](plans.md)'s `update`, not something you initiate.
