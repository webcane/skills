# Конфигурация и рабочие файлы

## Пути

Все команды в `SKILL.md` даны относительно **каталога скилла**
(`skills/python-algo-coach/` в репозитории, или каталог установки в
`~/.claude/skills/python-algo-coach/`). Определи его один раз в начале сессии и
дальше используй абсолютный путь.

| Что | Путь |
|---|---|
| Харнесс (единственный скрипт) | `scripts/run_tests.py` |
| Банк задач | `references/PROBLEMS.json` |
| Паттерны и шаблоны | `references/PATTERNS.md` |
| Чек-лист разбора | `references/REVIEW-CHECKLIST.md` |
| Эталонные решения | `references/solutions/<id>.py` |

## Рабочий каталог пользователя

Решения пользователя пишутся в **его** текущий рабочий каталог, не в каталог
скилла:

```
algo-practice/
  two_sum.py              # решение пользователя
  ...
  algo-log.md             # лог тренировок (создаётся при первом решении)
```

Никогда не пиши в `references/solutions/` — там эталоны, они read-only.

## Требования

Python 3.9+ из стандартной библиотеки. Внешних зависимостей нет.
`signal.setitimer` (таймаут на тест) требует Unix — на macOS и Linux работает,
на Windows таймаут не сработает, остальное — да.

## Формат лога тренировок

Дописывай в `algo-log.md` после каждой закрытой задачи одну строку:

```markdown
| Дата | Задача | Паттерн | Тесты | Сложность | Подсказок | Заметка |
|------|--------|---------|-------|-----------|-----------|---------|
| 2026-07-28 | two_sum | hash_map | 4/4 | O(n)/O(n) | 0 | сразу вспомнил dict |
| 2026-07-28 | binary_search | binary_search | 7/7 | O(log n)/O(1) | 2 | границы: right = mid - 1 |
```

Столбец «Подсказок» — главный сигнал прогресса. Если по одному паттерну
подсказки нужны стабильно, предложи вернуться к соответствующему разделу
`PATTERNS.md`.

## Схема записи задачи в PROBLEMS.json

| Поле | Смысл |
|---|---|
| `id` | канонический идентификатор, он же имя файла эталона |
| `aliases` | альтернативные имена (например, `cybersec` → `number_of_islands`) |
| `func` | имя функции, которое ищет харнесс |
| `signature` | подпись для скаффолда |
| `target` | целевая сложность: `time`, `space` |
| `trap` | на чём в этой задаче спотыкаются — проверяй первым при разборе |
| `hints` | ровно 3 уровня: намёк → приём → почти спойлер |
| `compare` | `exact` / `unordered` / `groups` / `inplace` / `inplace_k` |
| `arg_types` | построение аргументов: `null` / `linked_list` / `tree` |
| `return_type` | `null` / `linked_list` / `tree` |
| `tests` | список `{args, expected}` |

### Как добавить задачу

1. Добавь объект в `references/PROBLEMS.json` со всеми полями выше.
2. Положи эталон в `references/solutions/<id>.py` с функцией `func`.
3. Прогони самопроверку — она обязана остаться полностью зелёной:
   ```bash
   python3 scripts/run_tests.py --all-reference
   ```
4. Убедись, что тесты **ловят** типичный баг: напиши нарочно неверный вариант и
   прогони его. Тест, который проходит и с багом, бесполезен.
5. Подними `metadata.version` в `SKILL.md` и добавь запись в `CHANGELOG.md`
   под `## [Unreleased]`.

Комментаторы (`compare`) выбираются так: порядок ответа важен → `exact`; ответ —
множество → `unordered`; ответ — список групп → `groups`; функция мутирует
первый аргумент → `inplace`; мутирует и возвращает длину префикса → `inplace_k`.
