# Джентльменский набор паттернов (LeetCode Easy/Medium)

Двенадцать паттернов, которых достаточно для подавляющего большинства задач
уровня Easy и Medium. Для каждого: суть, признак «это он», ограничения и
питоновский шаблон.

Правило распределения: **Easy** обычно закрывается массивами, хешами и
базовыми циклами. **Medium** почти всегда требует комбинации — сортировка +
указатели, окно + хеш, BFS/DFS для графов, простой DP или стек.

---

## 1. Массивы — базовые техники

**Суть.** Прямой проход, перебор, подсчёт, модификация in-place. Часто с
дополнительными переменными или хранением состояния между итерациями.

**Признак.** «Найди максимум/минимум», «удали дубликаты», «объедини»,
«переверни», «проверь свойство массива».

**Ограничения.**
- Наивные решения — O(n²) (два вложенных цикла). На Medium требуют O(n) или O(n log n).
- В задачах in-place нельзя использовать дополнительную память сверх O(1).

**Шаблон — один проход с состоянием:**
```python
best = nums[0]          # НЕ 0 — иначе ломается на всех отрицательных
for x in nums[1:]:
    best = max(best, x)
```

**Ловушки.** Пустой массив. Массив из одного элемента. Все элементы
отрицательные. Инициализация нулём вместо `nums[0]`.

Задачи: `monotonic_array`, `longest_continuous_increasing_subarray`,
`best_time_to_buy_and_sell_stock`.

---

## 2. Хеш-таблицы (dict / set)

**Суть.** Хранение «ключ → значение» для быстрого поиска, подсчёта частот,
проверки уникальности. В среднем O(1) на вставку и запрос.

**Признак.** «Встречался ли уже», «сколько раз», «сгруппируй по признаку»,
«найди пару». Если внутренний цикл ищет что-то, что можно было запомнить —
это хеш.

**Ограничения.**
- Высокое потребление памяти — O(n).
- Требует хешируемых ключей: список нельзя, кортеж можно.
- Теоретически деградирует до O(n) при плохой хеш-функции.
- `dict` в Python 3.7+ **сохраняет порядок вставки**; `set` — нет.

**Шаблон — счётчик частот:**
```python
from collections import Counter, defaultdict

counts = Counter(nums)                    # значение -> сколько раз
groups = defaultdict(list)
for word in strs:
    groups["".join(sorted(word))].append(word)   # канонический ключ группы
```

**Шаблон — «видел ли раньше» за один проход:**
```python
seen = {}
for i, x in enumerate(nums):
    if target - x in seen:      # проверяем ДО вставки
        return [seen[target - x], i]
    seen[x] = i
```

**Ловушки.** Проверка `if x in some_list` — это O(n), а не O(1); нужен `set`.
Вставка до проверки позволяет использовать один элемент дважды.

Задачи: `two_sum`, `group_anagrams`, `valid_anagram`, `roman_to_integer`,
`unique_number_of_occurrences`, `intersection_of_two_arrays`.

## 3. Стек / Очередь / Deque

**Суть.** Стек (LIFO) — парсинг скобок, обратная польская запись, DFS,
«следующий больший элемент». Очередь (FIFO) — BFS. Deque — окно с удалением с
двух концов.

**Признак.** Важен **порядок вложенности**, а не только количество. «Последний
незакрытый», «ближайший слева/справа больший».

**Ограничения.**
- Доступ только к вершине/концам — произвольный доступ по индексу невозможен.
- `list.pop(0)` — O(n)! Для очереди всегда `collections.deque` и `popleft()`.

**Шаблон — стек скобок:**
```python
PAIRS = {")": "(", "]": "[", "}": "{"}
stack = []
for c in s:
    if c in PAIRS:
        if not stack or stack.pop() != PAIRS[c]:
            return False
    else:
        stack.append(c)
return not stack        # непустой стек в конце = незакрытые скобки
```

**Шаблон — монотонный стек («следующий больший»):**
```python
stack, nxt = [], {}
for num in nums:
    while stack and num > stack[-1]:
        nxt[stack.pop()] = num      # новый элемент разрешает всех меньших
    stack.append(num)
```

**Ловушки.** Забыть проверку пустого стека перед `pop()`. Забыть проверить
непустой стек после цикла. Подсчёт скобок вместо стека: `"([)]"` имеет верные
счётчики, но невалидна.

Задачи: `valid_parentheses`, `next_greater_element_i`.

## 4. Два указателя (Two Pointers)

**Суть.** Два указателя движутся по структуре с разных концов или с разной
скоростью. Превращает O(n²) в O(n).

**Разновидности.**
- **Встречные** (`left`, `right` с концов) — пара с заданной суммой, палиндром,
  максимальная площадь.
- **Быстрый и медленный** (`slow`, `fast`) — цикл в связном списке, середина списка.
- **Чтение/запись** (`read`, `write`) — модификация in-place за O(1) памяти.

**Ограничения.**
- Для встречных указателей данные должны быть **упорядочены** — иначе сначала
  сортировка O(n log n).
- Не работает для произвольных неотсортированных структур без предобработки.

**Шаблон — встречные указатели:**
```python
left, right = 0, len(arr) - 1
while left < right:
    ...
    if нужно_больше:
        left += 1
    else:
        right -= 1
```

**Шаблон — чтение/запись in-place:**
```python
write = 0
for read in range(len(nums)):
    if keep(nums[read]):
        nums[write], nums[read] = nums[read], nums[write]
        write += 1
return write        # длина «хорошего» префикса
```

**Шаблон — быстрый и медленный:**
```python
slow = fast = head
while fast and fast.next:      # это условие даёт ВТОРОЙ центр при чётной длине
    slow = slow.next
    fast = fast.next.next
```

**Ловушки.** Условие цикла `left < right` vs `left <= right` меняет ответ.
Условие в fast/slow определяет, какой из двух центральных узлов ты получишь.

Задачи: `container_with_most_water`, `move_zeroes`, `remove_element`,
`squares_of_a_sorted_array`, `valid_palindrome`, `middle_of_the_linked_list`.

## 5. Сортировка + указатели / бинарный поиск

**Суть.** Многие Medium начинаются с сортировки O(n log n), после чего
применяются быстрые техники. Классика: 3Sum, количество пар с разницей K.

**Признак.** Ответ не зависит от исходного порядка элементов, а зависит от их
значений и взаимного расположения по величине.

**Ограничения.**
- Сортировка **меняет исходный порядок** — нельзя, если порядок важен
  (например, задачи, где нужно вернуть индексы!).
- Добавляет O(n log n), что избыточно, если существует линейное решение.

**Шаблон — 3Sum: фиксируем один, two-pointers на остатке:**
```python
nums.sort()
for i in range(len(nums) - 2):
    if nums[i] > 0:
        break                                   # дальше только больше нуля
    if i > 0 and nums[i] == nums[i - 1]:
        continue                                # дедуп внешнего числа
    left, right = i + 1, len(nums) - 1
    while left < right:
        total = nums[i] + nums[left] + nums[right]
        if total < 0:
            left += 1
        elif total > 0:
            right -= 1
        else:
            res.append([nums[i], nums[left], nums[right]])
            left += 1
            right -= 1
            while left < right and nums[left] == nums[left - 1]:
                left += 1                       # дедуп внутренних
            while left < right and nums[right] == nums[right + 1]:
                right -= 1
```

**Ловушки.** Дедупликация — главная сложность. Нужна в двух местах: для
внешнего числа и после каждой найденной тройки.

Задачи: `three_sum`.

## 6. Бинарный поиск

**Суть.** Деление отсортированного диапазона пополам для поиска элемента,
границы или точки перехода. O(log n).

**Признак.** Данные отсортированы **или** существует монотонный предикат:
«для всех индексов до X ответ False, после — True».

**Ограничения.**
- Только для отсортированных или кусочно-монотонных данных.
- Off-by-one в границах — классическая проблема номер один.
- Сложно применить, когда нет чёткого порядка.

**Дисциплина границ — выбери одну схему и не смешивай:**

| Схема | Условие цикла | Обновления | Когда |
|---|---|---|---|
| `[left, right]` включительно | `while left <= right` | `left = mid + 1` / `right = mid - 1` | поиск точного значения |
| `[left, right)` полуоткрытый | `while left < right` | `left = mid + 1` / `right = mid` | поиск **границы** |

**Шаблон — точное значение:**
```python
left, right = 0, len(nums) - 1
while left <= right:
    mid = (left + right) // 2
    if nums[mid] == target:
        return mid
    if nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1
return -1
```

**Шаблон — поиск границы (минимум в повёрнутом массиве):**
```python
left, right = 0, len(nums) - 1
while left < right:                 # без равенства!
    mid = (left + right) // 2
    if nums[mid] > nums[right]:
        left = mid + 1              # перелом строго правее
    else:
        right = mid                 # mid ещё может быть ответом
return nums[left]                   # left == right
```

**Ловушки.** `right = mid` при `while left <= right` = бесконечный цикл.
Обязательные тесты: массив из одного элемента, отсутствующий target, «поворота
не было» (`[11,13,15,17]`).

Задачи: `binary_search`, `search_a_2d_matrix`,
`find_minimum_in_rotated_sorted_array`, `single_element_in_a_sorted_array`,
`find_k_closest_elements`.

## 7. Скользящее окно (Sliding Window)

**Суть.** Подмассив/подстрока переменной или фиксированной длины между двумя
границами. Правая граница расширяет окно, при нарушении условия левая сужает.

**Признак.** «Самая длинная/короткая непрерывная подстрока с условием»,
«подмассив фиксированной длины K».

**Ограничения.**
- Только для **последовательных** данных (массивы, строки).
- Правая граница должна двигаться **монотонно вперёд**.
- **Не работает при отрицательных числах**, если условие на сумму: сумма
  перестаёт быть монотонной при расширении окна. Тогда — префиксные суммы.

**Шаблон — окно переменной длины:**
```python
last_seen = {}
left = best = 0
for right, c in enumerate(s):
    if c in last_seen:
        left = max(left, last_seen[c] + 1)    # max ОБЯЗАТЕЛЕН
    last_seen[c] = right
    best = max(best, right - left + 1)
```

**Шаблон — окно фиксированной длины K (инкрементальное обновление):**
```python
window = Counter(s[:k])
for i in range(k, len(s)):
    window[s[i]] += 1              # входит
    out = s[i - k]
    window[out] -= 1               # выходит
    if window[out] == 0:
        del window[out]            # иначе сравнение Counter'ов врёт
```

**Ловушки.** Без `max()` левая граница уезжает назад: на `"abba"` наивный
вариант даёт 3 вместо 2. Нулевые значения в `Counter` мешают сравнению `==`.
Пересчёт всего окна на каждом шаге превращает O(n) в O(n·k).

Задачи: `longest_substring_without_repeating`, `find_all_anagrams_in_a_string`.

## 8. BFS / DFS на графах, сетках и деревьях

**Суть.** Обход в ширину (BFS — очередь) или в глубину (DFS — стек или
рекурсия). Пути, связность, уровни, циклы, «заливка» области.

**Признак.** Сетка со связными областями, дерево, граф зависимостей.
Кратчайший путь в невзвешенном графе — **всегда BFS**. Разбиение по уровням —
BFS. Просто «обойти всё» — что угодно, DFS короче.

**Ограничения.**
- BFS требует O(ширина) памяти, DFS — O(глубина).
- Глубокая рекурсия DFS → `RecursionError` (в Python лимит ~1000).
- Без множества посещённых узлов обход **зациклится**.
- Неэффективен для перебора всех путей в плотных графах.

**Шаблон — BFS по сетке («заливка»):**
```python
from collections import deque

DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))    # диагонали НЕ смежные
queue = deque([(r, c)])
grid[r][c] = "0"                              # помечаем сразу при добавлении
while queue:
    cr, cc = queue.popleft()
    for dr, dc in DIRS:
        nr, nc = cr + dr, cc + dc
        if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == "1":
            grid[nr][nc] = "0"
            queue.append((nr, nc))
```

**Шаблон — BFS по уровням дерева:**
```python
queue = deque([root])
while queue:
    for _ in range(len(queue)):     # фиксируем размер = границы уровня
        node = queue.popleft()
        ...
```

**Шаблон — DFS рекурсией по дереву:**
```python
def depth(node):
    if node is None:                # база — None, а не лист
        return 0
    return 1 + max(depth(node.left), depth(node.right))
```

**Ловушки.** Помечать посещённым при извлечении, а не при добавлении → узел
попадёт в очередь несколько раз. Переиспользование входной сетки как `visited`
портит вход — на интервью это стоит проговорить. `list.pop(0)` вместо
`deque.popleft()`.

Задачи: `number_of_islands`, `max_depth_binary_tree`,
`binary_tree_level_order_traversal`.

## 9. Базовое динамическое программирование

**Суть.** Разбиение на перекрывающиеся подзадачи с сохранением результатов
(мемоизация или таблица).

**Признак.** «Сколько способов», «максимум/минимум по последовательности
решений», и наивная рекурсия считает одно и то же многократно.

**Ограничения.**
- Требует оптимальной подструктуры и перекрывающихся подзадач — не всегда очевидно.
- Пространство состояний растёт: O(n) или O(n²) памяти.
- На Medium встречается в простых формах: 1D DP, редко 2D.

**Формулировка состояния — обязательный шаг.** Проговори вслух: «`dp[i]` — это
_____ для префикса длины i». Без этого дальше идти нельзя.

**Шаблон — Кадане (максимальный подмассив):**
```python
cur = best = nums[0]          # НЕ 0
for x in nums[1:]:
    cur = max(x, cur + x)     # продолжить или начать заново
    best = max(best, cur)
```

**Шаблон — 1D DP с двумя переменными вместо таблицы:**
```python
prev = cur = 0
for x in nums:
    prev, cur = cur, max(cur, prev + x)     # House Robber
return cur
```

**Шаблон — мемоизация «бесплатно»:**
```python
from functools import cache

@cache
def solve(i): ...
```

**Ловушки.** Инициализация нулём при возможных отрицательных значениях.
Рекурсия без мемоизации: `climbing_stairs(45)` без неё не досчитает. Если
хватает O(1) памяти — таблица избыточна, и на интервью это заметят.

Задачи: `maximum_subarray`, `climbing_stairs`, `house_robber`.

## 10. Жадные алгоритмы (Greedy)

**Суть.** На каждом шаге локально оптимальное решение в надежде на глобальный
оптимум.

**Признак.** Интервалы, задачи на монеты (при «хороших» номиналах), разбиение
на части.

**Ограничения.**
- Работает **только** там, где жадный выбор доказуемо ведёт к оптимуму.
- Легко ошибиться, применив жадность там, где нужен DP. Проверка: `[2,1,1,2]`
  в House Robber — жадное «брать через один» даёт 3, правильный ответ 4.

**Требование интервью: обоснование.** Скажи, **почему** жадный выбор безопасен.
Для `container_with_most_water`: сдвиг более высокой стороны не может увеличить
площадь, так как ширина уменьшается, а высота ограничена меньшей стороной.

**Шаблон — предподсчёт + жадная граница:**
```python
last = {c: i for i, c in enumerate(s)}     # предподсчёт
start = end = 0
for i, c in enumerate(s):
    end = max(end, last[c])                # тянем границу
    if i == end:                           # можно закрывать
        res.append(end - start + 1)
        start = i + 1
```

Задачи: `partition_labels`, `best_time_to_buy_and_sell_stock`,
`container_with_most_water`.

## 11. Префиксные суммы (Prefix Sum)

**Суть.** Массив префиксных сумм даёт сумму любого подмассива за O(1). В паре с
хеш-таблицей — поиск подмассивов с заданной суммой.

**Признак.** «Сумма подмассива равна K», много запросов на сумму диапазона,
**и в данных есть отрицательные числа** (иначе хватило бы окна).

**Ограничения.**
- Требует предподсчёта O(n) и O(n) памяти.
- Бесполезна без запросов на суммы диапазонов.

**Ключевое тождество.** `sum(nums[i:j]) == prefix[j] - prefix[i]`. Значит,
подмассив с суммой k существует ⟺ встречалось значение `prefix[j] - k`.

**Шаблон:**
```python
counts = {0: 1}         # эта единица — за подмассивы, начинающиеся с индекса 0
running = res = 0
for x in nums:
    running += x
    res += counts.get(running - k, 0)      # сначала считаем
    counts[running] = counts.get(running, 0) + 1    # потом вставляем
return res
```

**Ловушки.** Забыть `{0: 1}` — потеряются все подмассивы от начала.
Вставить `running` до подсчёта — на `k == 0` получишь лишние совпадения.

Задачи: `subarray_sum_equals_k`.

## 12. Битовая манипуляция

**Суть.** Побитовые операции (`&`, `|`, `^`, `~`, `<<`, `>>`) для задач с
числами, поиска уникальных элементов, работы со степенями двойки.

**Признак.** «Каждый элемент дважды, кроме одного» → XOR. «Степень двойки» →
`n & (n - 1) == 0`. Явный запрет на арифметические операторы.

**Ограничения.**
- Применима к целым числам и флагам.
- Код трудно читать и отлаживать.
- На Medium встречается редко и в специфических задачах.

**Полезные тождества.**
```python
x ^ x == 0          # парные сокращаются
x ^ 0 == x
n & (n - 1)         # сбрасывает младший установленный бит
n & 1               # младший бит: чётность
mid -= mid & 1      # округление вниз до чётного
a ^ b               # сумма без переноса
(a & b) << 1        # перенос
```

**Отдельная беда Python: целые неограниченные.** Наивный цикл переноса на
отрицательных числах не завершится. Нужна маска 32 бит и обратное
преобразование:
```python
MASK, MAX_INT = 0xFFFFFFFF, 0x7FFFFFFF
a, b = a & MASK, b & MASK
while b:
    a, b = (a ^ b) & MASK, ((a & b) << 1) & MASK
return a if a <= MAX_INT else ~(a ^ MASK)
```

**Ловушки.** Цикл «пока n != 0» вместо ровно 32 итераций в `reverse_bits` теряет
ведущие нули: для `n = 1` ответ должен быть `2147483648`.

Задачи: `reverse_bits`, `sum_of_two_integers`, `missing_number`.

## Связные списки (сопутствующая техника)

Не отдельный паттерн, а структура, на которой применяются указатели.

**Два приёма, закрывающих большинство задач:**

1. **Фиктивная голова (dummy node)** — избавляет от особого случая для первого
   узла при построении нового списка.
2. **Три указателя `prev / cur / nxt`** — для разворота. Порядок операций
   критичен: сохранить `next` **до** перезаписи.

```python
dummy = ListNode()
tail = dummy
...
tail.next = ListNode(value)
tail = tail.next
return dummy.next
```

```python
prev, cur = None, head
while cur:
    nxt = cur.next        # сохранить ДО перезаписи
    cur.next = prev
    prev = cur
    cur = nxt
return prev
```

**Ловушки.** Потеря ссылки на остаток списка = бесконечный цикл. Пустой список
(`None`) — всегда отдельный тест. Случайно созданный цикл в ответе.

Задачи: `reverse_linked_list`, `add_two_numbers`, `middle_of_the_linked_list`.

## Шпаргалка: признак → паттерн

| Что видишь в условии | Первая гипотеза |
|---|---|
| «встречался ли», «сколько раз», «сгруппируй» | хеш-таблица |
| отсортированный массив + поиск пары | встречные указатели |
| отсортированный массив + поиск одного значения/границы | бинарный поиск |
| «самая длинная/короткая непрерывная подстрока» | скользящее окно |
| сумма подмассива = K, есть отрицательные | префиксные суммы + хеш |
| сумма подмассива = K, все положительные | скользящее окно |
| правильность вложенности, «ближайший больший» | стек |
| кратчайший путь в невзвешенном графе, уровни | BFS |
| связные области в сетке, обход дерева | DFS или BFS |
| «сколько способов», max/min по цепочке решений | DP |
| интервалы, разбиение на части | greedy (+ обоснование) |
| «каждый дважды кроме одного», степень двойки | XOR / битовые операции |
| in-place, O(1) памяти | указатели чтение/запись |
| цикл или середина связного списка | быстрый и медленный |
| нужны все комбинации/перестановки | backtracking |
