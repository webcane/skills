# Engineering Dialectic

Получить инженерное решение с проверенными основаниями, границами применимости
и исполнимым планом проверки. Язык результата — язык пользователя.

## Выбор режима

| Режим | Когда применять |
| --- | --- |
| `independent` — по умолчанию | Неясна полнота вариантов, сомнительны предпосылки или недостаточно оснований |
| `positions` | Нужно сравнить известные варианты или явно заданные инженерные приоритеты |
| `hybrid` | Сначала проверить рамку независимо, затем подробно сравнить обнаруженные варианты |

Прямой выбор режима пользователем имеет приоритет. Подробности и ограничения:
[сравнение методов](references/method-comparison.md). Примеры запросов:
[области применения](references/use-cases.md); их не нужно читать при каждом запуске.

## Выполнение

1. Прочитай [протокол](references/protocol.md) и
   [контракт свидетельств](references/evidence-contract.md).
2. Проверь доступность отдельных свежих контекстов и технического запрета
   записей у исполнителей. Модель выбирает пользователь или сборщик профилей:
   зафиксируй фактическую и ограничение выбора. Проверь, не раскрывает ли
   автоматически добавленный контекст ответ, и выставь `blindness`.
   Зафиксируй ограничения среды. Не изображай независимых агентов внутри одной сессии.
3. Зафиксируй предварительную позицию ведущего до независимого ответа.
   Подготовь нейтральное задание, отделив обязательные требования от гипотез.
4. Передавай исполнителям только соответствующий раздел
   [промптов ролей](references/role-prompts.md) и их входной пакет.
   Слепому решателю не передавай этот skill целиком: он может раскрыть исходные варианты.
5. Получи независимое решение, затем проверку дискриминатора; выполни синтез.
   В `positions` сначала получи сильные версии вариантов и перекрёстные возражения,
   затем передай утверждения дискриминатору. Не называй этот режим слепым.
6. Для ответственных решений выбери применимые экспертные роли из протокола.
   Их задача — опровергнуть синтез конкретным сценарием отказа.
7. Закрой принятые находки либо явно оставь блокирующие проверки открытыми.
   Используй [шаблон решения](assets/decision-template.md).

## Границы выполнения

Решатель, дискриминатор, защитники вариантов и эксперты только читают. Никаких
сборок, тестовых запусков, worktree, изменений файлов, DDL или DML, включая
`IF EXISTS`. Недоступные или изменяющие среду замеры перечисляй как задания.
Доступ к БД — только через проверенный инструмент и отдельные права чтения:
`SELECT` без изменяющих состояние функций и обычный `EXPLAIN`, без `ANALYZE`.

Оркестратор также не реализует решение в рамках анализа. Если пользователь
попросил сохранить результат, записывает его сам либо передаёт родительскому
агенту с правом записи. По умолчанию результат возвращается в чат. Существующие
артефакты не перезаписывай без указания пользователя.

Полнота поиска и независимость ошибок не гарантируются числом агентов.
Согласие без исключённой альтернативы не является подтверждением. При
недостатке фактов результат — `needs-evidence`, а не вымышленный консенсус.
