# HADI Cycle — Fast Hypothesis Testing

> H — Hypothesis. A — Action. D — Data. I — Insights. A short loop that
> tests a hypothesis quickly and cheaply, then decides what to do next.
> The point is to learn from small failures early instead of spending
> resources validating weak ideas.

## Origin

A lean / growth-engineering iteration pattern (the HADI cycle) used in
startup practice as a lightweight alternative to heavier experiment
design. It is a validation method — it does not generate hypotheses, it
tests them.

## Application to Problem Analysis

After a hypothesis is formed, HADI tests it in one short cycle.

### 1. Hypothesis

Formulate the hypothesis as a testable statement.

> "Adding a free trial will raise conversion."

### 2. Action

Design the smallest experiment that can generate data about the
hypothesis.

### 3. Data

Collect the data the experiment produces. Record it before
interpreting it.

### 4. Insights

Draw the conclusion and decide what to do next: keep the hypothesis,
revise it, or discard it.

## When to Use

A hypothesis that has been formed and needs cheap validation, a set of
small experiments, or a "test it and see" situation where speed matters
more than statistical rigor.

## Output

The hypothesis, the experiment design, the data collected, and the
decision (keep / revise / discard) with the insight behind it.
