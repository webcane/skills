# cane-wiki-init

Вики ведёт агент `cane-wiki` по паттерну Karpathy LLM Wiki: источники в `inbox/` → `raw/`, страницы в `Wiki/`, индекс, журнал, режимы query / ingest / update / lint / prune. Скил готовит всё, что агенту нужно для работы, и ничего не пишет поверх существующих файлов без подтверждения.

Материалы для генерации лежат в `references/`:

| Файл | Назначение |
|---|---|
| `presets.yml` | Пресеты категорий страниц (значения для раздела `categories`) и категории, создаваемые всегда |
| `AGENTS.md.tmpl`, `CLAUDE.md.tmpl`, `Schema.md.tmpl` | Снимки тонких документов vault |
| `templates/*.md` | Шаблоны страниц по категориям (Templater) |
| `prompts/*.md` | Промпты разбора по категориям (теги `agent-prompt`) |

Канонические шаблоны и промпты находятся в `references/` этого скила. Режимы работы вики описаны в агенте `cane-wiki`. Платформенные метки ниже имеют смысл и в исходном Agent Skill: `доступный инструмент запроса ввода или вопрос в чате` — задай вопрос доступным способом; `множественный выбор или перечисление вариантов в ответе` — разреши выбрать несколько вариантов (если интерфейс не умеет, попроси перечислить их текстом). Платформенные упаковщики заменяют эти метки на конкретные вызовы.

## Установка зависимостей

Если агент вызвал этот скил только из-за отсутствия `obsidian-markdown`, `obsidian-cli` или `defuddle`, не запускай опрос и не меняй vault. Запусти `scripts/install-obsidian-skills.sh codex` в Codex или `scripts/install-obsidian-skills.sh claude-code` в Claude Code из каталога этого скила. Скрипт ставит только отсутствующие скилы из `https://github.com/kepano/obsidian-skills`. Если сеть или запись недоступны, попроси пользователя выполнить подходящую команду:

```bash
# Codex
npx skills add https://github.com/kepano/obsidian-skills --skill obsidian-markdown --skill obsidian-cli --skill defuddle -g -a codex -y
# Claude Code
npx skills add https://github.com/kepano/obsidian-skills --skill obsidian-markdown --skill obsidian-cli --skill defuddle -g -a claude-code -y
```

После установки сообщи результат агенту и закончи этот вызов скила. Если зависимости недоступны, сообщи об этом явно.

## Шаг 0: определить состояние каталога

Целевой каталог — текущая рабочая директория. Проверь:

- есть `llm-wiki.yml` → режим **проверки и перенастройки** (шаг R);
- есть `.obsidian/`, но нет `llm-wiki.yml` → **существующий vault**, настройка вики поверх него;
- нет ни того, ни другого → предложи создать vault здесь. Без подтверждения ничего не создавай.

Убедись, что CLI Obsidian доступен (`obsidian help`). Если нет, продолжай, но предупреди: в режимах query и lint придётся искать файлами и по тексту, а ссылки и бэклинки проверить будет нечем.

## Шаг 1: опрос

Вопросы задавай через доступный инструмент запроса ввода или вопрос в чате, пачками не больше четырёх. Всё, что можно взять по умолчанию, не спрашивай.

Первая пачка:

1. **Язык заметок**: русский (по умолчанию) или английский. Влияет на тексты `AGENTS.md`, заголовки шаблонов и промптов.
2. **Режим индекса**: `hubs` (хаб на каждый неймспейс, по умолчанию) или `single` (один `Wiki/Index.md`).
3. **Автокоммит**: `ask` (по умолчанию) или `auto`. В любом случае слово «auto» в запросе включает автокоммит для одного вызова.
4. **Политика обновления по умолчанию**: `revise` (по умолчанию) или `append`.

Вторая пачка:

1. **Категории страниц** (множественный выбор или перечисление вариантов в ответе) из `presets.yml`. Предложи knowledge, reference, daily как базу; остальные по необходимости. Допускается своя категория: спроси название и поля, сформируй запись по образцу пресета.
2. **Неймспейсы**: покажи предложение из `namespace_hint` выбранных категорий и дай поправить.
3. **Скоропортящиеся категории** (множественный выбор или перечисление вариантов в ответе): только те, что могут устареть. Для выбранных спроси срок `stale_after_days`. Остальным ключ не добавляй.
4. **Исключения из revise**: категории, которые остаются append-only (по умолчанию из пресетов).

## Шаг 2: генерация

Читай значения из ответов и `presets.yml`. Перед записью каждого файла проверь, существует ли он. Существующий файл заменяй только после показа diff и подтверждения; иначе пропусти и отметь в отчёте.

Создай:

1. **`llm-wiki.yml`** по образцу ключей: `tool`, `wiki_path`, `namespaces`, `excluded_from_git`, `root_pages`, `inbox_dir`, `raw_dir`, `index`, `log`, `access_log`, `query`, `prompts`, `update_policy`, `categories`, `lint`, `critic`, `git`. Категории и `update` берутся из пресетов с учётом ответов; категории `hub` и `prompt` добавляются всегда (раздел `always` в `presets.yml`). Для `critic` задай `report_dir: Daily Notes`, `exclude_namespaces: [Books, People, Companies, Meta, Interview]`, `exclude_types: [application, daily, hub, prompt, feedback, decision, schema]`, `target_pages_per_run: 100`. Значения можно менять в конфиге без правки агента.
2. **`AGENTS.md`** из шаблона, с учётом языка. **`CLAUDE.md`** создавай только при работе в Claude Code. Не добавляй в них значения из конфига и не дублируй один документ в другом.
3. **Каталоги**: `Wiki/`, `inbox/`, `raw/`, `templates/` и каталог `critic.report_dir` (по умолчанию `Daily Notes/`).
4. **`Wiki/Schema.md`** из шаблона: оставь только описание выбранных категорий.
5. **Шаблоны страниц** `templates/<категория>.md` для выбранных категорий, у которых они есть в `references/templates/`.
6. **Индекс**: при `hubs` корневой хаб на каждый неймспейс (`Wiki/<NS>.md` по форме хаба из `Schema.md`); при `single` файл `index.path`.
7. **Журналы**: файл `log.path` (`log: true`, `type: reference`) и `access_log.path` с шапкой и первой строкой.
8. **Промпты**: каталог `prompts.namespace` с промптами для выбранных категорий, у которых они есть в `references/prompts/`, и хаб этого неймспейса. Теги страниц: `agent-prompt` и имя категории.
9. **`.gitignore`**: `inbox/` и `raw/` (добавь недостающие строки, существующие не трогай).
10. **`.obsidian/app.json`**: `newLinkFormat: relative` по согласию пользователя. Если файл есть, меняй только эту настройку.
11. **Агенты**: в Claude Code, если оба агента уже доступны через плагин `cane-wiki`, не копируй их в vault. Иначе установи `.claude/agents/cane-wiki.md` и `.claude/agents/cane-wiki-critic.md` из пользовательской установки или checkout. В Codex убедись, что доступны `~/.codex/agents/cane-wiki.toml` и `~/.codex/agents/cane-wiki-critic.toml` либо их проектные аналоги; если нет, предложи `bash scripts/install-cane-wiki-agents-codex.sh` из checkout. `cane-wiki` вызывает `cane-wiki-init` для vault без `llm-wiki.yml`, при явной просьбе перенастроить его или при нехватке Obsidian skills.
12. **Git**: предложи `git init`, если каталог не репозиторий.

## Шаг R: проверка и перенастройка существующей вики

1. Разбери `llm-wiki.yml` (`ruby -ryaml -e 'YAML.load_file("llm-wiki.yml")'` или `python3`, если установлен модуль yaml). Сообщи о синтаксических ошибках.
2. Проверь, что каждый ключ, нужный агентам, на месте: `index`, `log`, `access_log`, `query`, `prompts`, `update_policy`, `categories`, `lint`, `critic`, `git`. При отсутствии `critic` предложи добавить значения из шага 2 с показом diff.
3. Проверь, что файлы по путям из конфига существуют (журнал, Access-Log, индекс/хабы, промпты выбранных категорий) и что у каждой категории есть шаблон или явная пометка, что его нет.
4. Проверь расхождения: значения (пути, пороги) повторяются в прозе `AGENTS.md`, `Schema.md`, скила; если существует `CLAUDE.md`, проверь общие абзацы с `AGENTS.md`.
5. Предложи исправления списком. Любое изменение файла делается только после показа diff и подтверждения.

## Шаг 3: проверка и отчёт

1. `llm-wiki.yml` разбирается без ошибок; каждая категория из `categories` имеет запись в `Schema.md`.
2. Все пути из конфига существуют.
3. `obsidian help` отвечает.
4. Выведи список созданных, изменённых и пропущенных файлов и следующий шаг: положить файл в `inbox/` и вызвать `cane-wiki` в режиме `ingest`. В Claude Code после установки файла агента проверь, что он доступен в новой сессии.

## Границы

- Ничего не удаляй и не перезаписывай без подтверждения.
- Не создавай страницы-знания и не заполняй вики содержимым: скил готовит каркас.
- Не коммить. `git init` выполняется только по согласию, первый коммит делает пользователь.
